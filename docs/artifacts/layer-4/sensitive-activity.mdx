<GovernanceArtifact
  title="Sensitive Activity"
  layer={4}
>

<Purpose>
Name and bound the actions that introduce risk; the hinge between definition layers and measurement layers.
</Purpose>

<LayerRole>
Layer 4 — sensitive activities. In Gemara this layer is conceptual (no dedicated schema by design): it is the activity being evaluated, not another catalog file.
</LayerRole>

<WhyYouNeedThis>
Definition catalogs without an activity focus drift into documentation. Measurement logs without a named activity cannot explain *what* was evaluated. Layer 4 keeps both sides honest.
</WhyYouNeedThis>

<Contains>

- Activity descriptions and scope (prose / twin / request model)—not a Gemara catalog type
- Binding to actors, targets, context and environment when evaluated

</Contains>

<KeyFields>

- Clear activity identity in operational systems (e.g. “contribute company-interest PR”)
- Links into policy applicability and evaluation `target` resources

</KeyFields>

<LinksUpstream>

- [Guidance](/docs/artifacts/layer-1/guidance), [Control](/docs/artifacts/layer-2/control), [Policy](/docs/artifacts/layer-3/policy) define what good looks like for the activity

</LinksUpstream>

<LinksDownstream>

- [Evaluation Log](/docs/artifacts/layer-5/evaluation-log) inspects instances of the activity
- [Enforcement Log](/docs/artifacts/layer-6/enforcement-log) acts on those results

</LinksDownstream>

<Example>

The sensitive activity being governed is employee contribution of open source software from within the organisation. Catalogs and logs organise around that activity — for example:

- **Activity:** writing open source software and attempting to contribute it from within the organisation
- **Capabilities that create surface:** `public-source-publication`, `company-infrastructure-contribution`
- **Vectors that can go wrong:** `accidental-sensitive-commit`, `ungoverned-project-contribution`
- **Control on the path:** `foss-ctl-008-data-leakage-review` (non-public information review before publish)
- **Policy frequency:** `ap-foss-008-data-leakage-review` runs `per-contribution`

Instances of the activity look like a named engagement and pull request, for example `example-corp/internal-tools` PR #417 in a company-moderated environment — the same target referenced by evaluation and enforcement logs.

</Example>

<AntiPatterns>

- Treating “application” inventory as if it were the sensitive activity
- Skipping Layer 4 and jumping from policy text to screenshots
- Activities so broad that no assessment plan can apply

</AntiPatterns>

<Discussion>

Sensitive activity is also Factor I of Ten Factor Governance. Gemara’s Layer 4 exists so automated governance stays centred on actions—not only on documents. Pair this page with governance twins and structured requests when you operationalise it.

</Discussion>
