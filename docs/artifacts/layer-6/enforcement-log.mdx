<GovernanceArtifact
  title="Enforcement Log"
  gemaraType="EnforcementLog"
  layer={6}
>

<Purpose>
Record preventive or remediative actions taken in response to evaluation results.
</Purpose>

<LayerRole>
Layer 6 — measurement. Enforcement closes the loop: block, notify, remediate, or explicitly clear, with justification back to Layer 5.
</LayerRole>

<WhyYouNeedThis>
Failed evaluations that nobody acts on are theatre. Enforcement logs prove the gate or remediation fired—and why—using policy method ids and evaluation justification.
</WhyYouNeedThis>

<Contains>

- **ActionResult** entries with disposition, steps, timestamps
- Links to enforcement/evaluation methods
- Justification pointing at assessment logs / requirements / plans

</Contains>

<KeyFields>

- `method` referencing policy enforcement methods
- `justification.assessments[]` → evaluation log + requirement + plan
- Disposition and step history

</KeyFields>

<LinksUpstream>

- [Evaluation Log](/docs/artifacts/layer-5/evaluation-log)
- [Policy](/docs/artifacts/layer-3/policy) enforcement methods

</LinksUpstream>

<LinksDownstream>

- [Audit Log](/docs/artifacts/layer-7/audit-log) cites enforcement evidence
- Operational ticketing / merge gates consuming the same dispositions

</LinksDownstream>

<Example>

Enforcement after the failed data-leakage evaluation: merge blocked and contributor/OSPO notified:

```yaml
metadata:
  id: foss-enforcement-internal-tools-pr417
  type: EnforcementLog
  date: "2026-07-06T09:15:10Z"
  description: >
    Enforcement actions taken after failed data-leakage evaluation for PR #417

disposition: Enforced

target:
  id: foss-engagement-internal-tools
  name: example-corp/internal-tools
  environment: company-moderated

actions:
  - disposition: Enforced
    method:
      reference-id: foss-contribution-policy
      entry-id: em-foss-block-merge
    message: >
      Blocked merge of pull request #417: secret scan reported uncleared AWS
      access key (GL-2026-07-06-00417-01).
    steps:
      - ospo/enforcement/github.setPullRequestMergeBlocked
      - ospo/enforcement/github.postCheckRunFailure
    justification:
      assessments:
        - result: Failed
          requirement:
            reference-id: foss-contribution-controls
            entry-id: foss-ctl-008-data-leakage-review.ar01
          plan:
            reference-id: foss-contribution-policy
            entry-id: ap-foss-008-data-leakage-review
          log:
            reference-id: foss-eval-internal-tools-pr417
            entry-id: foss-ctl-008-data-leakage-review

  - disposition: Enforced
    method:
      reference-id: foss-contribution-policy
      entry-id: em-foss-notify-noncompliance
    message: >
      Notified contributor and OSPO of failed secret-scan finding on PR #417.
    steps:
      - ospo/enforcement/notify.emailContributor
      - ospo/enforcement/notify.postOspoSlackAlert
```

</Example>

<AntiPatterns>

- Enforcement with no link back to an evaluation
- Chat-only blocks with no log artifact
- Methods invented ad hoc outside policy

</AntiPatterns>

<Discussion>

Enforcement is how Continuous Governance becomes substantive. Gemara’s insistence on justification links is what keeps gates explainable instead of mysterious red builds.

</Discussion>
